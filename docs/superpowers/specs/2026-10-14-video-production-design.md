# 视频模块：从制作包到成片（配音 · 画面 · 渲染）

接 2026-10-12 的视频模块设计。那一版只交付制作包，字幕时间轴靠模型估的秒数，成片要人去剪。这一版参考开源社区高星项目的生成链路，补上配音、画面和成片渲染，让一条健康科普短视频能在应用里直接出 MP4。仍然不代发布。

## 新流水线（8 步）

1. **选题**：不变。
2. **口播脚本**：提示词改为先定「讲解结构」（概念 / 步骤 / 清单 / 故事）和一句话结论，再写口播；不照资料顺序复述。
3. **分镜**：每镜新增 `role`（开场钩子、讲问题、讲概念、步骤、证据、结论、行动建议）和 `imagePrompt`（配图提示词）；`caption` 明确为「画面大字」（≤12 字），不再当字幕用。
4. **配音与字幕**：逐镜 TTS，取真实音频时长作为镜头时长（每镜之后留 0.35 秒气口）。字幕从口播按句切分，每行 ≤14 字，时长在镜头内按字数分配。可以选「不配音」，此时时间轴用分镜秒数。
5. **画面**：三套竖版模板（暖米、素白、深夜），字号按中老年可读性定（字幕 66px、画面大字 72–120px，重要内容都在 1540px 以上，避开抖音 / 视频号底部信息栏）。画面跟着镜头作用变：开场、结论、提醒用实底强调色卡片，其余用浅色卡片，大字上方一行引导语（「为什么会这样」「第 2 步」）。画面大字先找一行放得下的最大字号，放不下用多行并均分，不出单字孤行。配图两种模式：纯文字卡片（默认，不花钱）或逐镜 AI 配图（复用公众号图片接口）。可先渲染每镜一帧的预览，渲染前自查。
6. **成片**：画面是时间的纯函数——`motionAt(timing, t)` 算出这一刻的动效参数，写成 `<html style>` 上的 CSS 变量（页面不跑脚本、不用 CSS 动画），Electron 离屏窗口每段字幕载入一次页面，逐张改写变量再截图。帧计划按 30fps 逐帧计算，相邻帧画面相同就合并成一张静帧加帧数，所以只在有动效的地方逐帧截图（镜头开头 0.6 秒入场、字幕每亮一个字、配图推近每走一步），ffconcat 时长按帧数换成微秒不漂移。ffmpeg 拼接后合入口播音轨与可选背景音乐（默认 12% 音量、结尾 2 秒淡出），输出 H.264 + AAC 的 MP4。
7. **镜头内动效**（2026-10-15，按中老年观众收着做）：大字和引导语淡入并由 92% 推近到 100%；配图淡入后整镜推近 4%，落点用标题 + 镜头序号做种子的伪随机；进度条当前一格填满；有配音时字幕逐字由正文色变强调色。标题、页脚、卡片底色不动。片头第一镜不做入场（第一帧常被当作预览图）。逐字高亮按整镜分配：渲染前用 silencedetect 测出每镜配音真正出声的区间（系统语音句首约 0.2 秒、句尾约 0.9 秒静音），标点和换行处各算两个字的停顿。
8. **封面**：不变（可选）。
9. **制作包**：新增成片 `video.mp4`（有且未过期时才带上），`captions.srt` 改用真实时间轴。

## 素材账本与失效规则

- 配音、配图都按内容哈希登记在 `assets_json`：配音的键是「声音参数 + 口播文本」，配图的键是「配图提示词 + 尺寸」。改了某一镜的口播，只有这一镜需要重配；其它镜头的音频原样复用。
- 声音参数在点击「生成配音」时快照进账本；之后改全局配音设置不会让已有项目悄悄变声，重新配音才会换。
- 成片记录一个签名（分镜、时长、配音键、配图键、模板、背景音乐）。任何一项变化，成片标成「需要重新渲染」，导出时不再带旧成片。
- 用户可改的渲染选项（配音方式、模板、配图模式、背景音乐、页脚）存 `options_json`，走 `video:update`；`assets_json` 只由主进程写，界面保存不会覆盖。

## 配音来源

- **系统语音**（默认）：Windows 自带语音（System.Speech，如「Microsoft Huihui」），离线、免费，音质一般。一次 PowerShell 进程合成全部镜头。
- **OpenAI 兼容接口**：`POST {baseUrl}/audio/speech`，覆盖 OpenAI、硅基流动（CosyVoice / IndexTTS）等网关。地址、模型、音色、语速存 `userData/video-tts.json`，key 存 secret-store 的 `video-tts-api-key.bin`。
- 每次 TTS 都由用户点按钮触发，不会在自动生成里偷偷花钱。

## 预检与错误处理

- 渲染前预检：找不到 ffmpeg / ffprobe（PATH 或环境变量 `SYDNEY_FFMPEG`）、配音没完成或已过期、AI 配图模式下有镜头缺图，都当场报错，不开始渲染。
- 渲染写到临时文件，成功后再改名；失败时清理本次的临时帧，不留半个视频。
- 长操作按任务加锁，进度通过 `video:progress` 事件推给界面。

## 模块边界

- `video-pipeline.ts`：步骤状态、字幕切句、时间轴、SRT、成片 / 预览签名、导出门槛（纯函数，渲染进程也用）。
- `video-production.ts`：渲染选项与素材账本的归一化、内容哈希、配音 / 配图的键与新鲜度、声音参数快照（纯函数，渲染进程也用）。
- `video-image-prompts.ts`：视频视觉提示词的唯一入口；分镜 `image_prompt` 规则、逐镜配图尺寸与完整模板、9:16 竖版封面模板都在这里，不再混在脚本工作流或公众号图片配置中。
- `video-compose.ts`：帧 HTML 模板、帧计划、ffconcat 清单与 ffmpeg 参数（纯函数，可单测）。改模板排版要把 `FRAME_TEMPLATE_VERSION` 加一，旧成片随之标成过期。
- `video-tts.ts`：配音设置读写、OpenAI 兼容请求、系统语音脚本。
- `video-render.ts`：依赖 Electron 与子进程的部分：离屏截图、ffprobe、ffmpeg。
- `ipc/video.ts`：`video:voice`、`video:images`、`video:preview`、`video:render`、`video:tts:*`、`video:bgm:choose`、`video:open-video`。

- 拼图自查改掉的三个问题：① 逐字高亮落后声音约 0.7 秒（系统语音自带句首句尾静音）→ 改为按静音检测出的出声区间、整镜分配并计入停顿；② 片头第一帧是空卡片 → 第一镜不做入场；③ 入场时大字有一段发灰发粉的半透明期（实底卡片上尤其明显）→ 文字透明度提前到入场 60% 时就满。
- 未实测：AI 配图模式的推近（隔离环境没有图片接口）；只有单测覆盖。

| [RayVentura/ShortGPT](https://github.com/RayVentura/ShortGPT) | 约 8 千 | 不同创作阶段使用独立 prompt 模板和输出契约，脚本、标题、图片提示词不混在一次调用里。 |

落地的自有规则：

1. **选题**：5 个候选至少覆盖三种角度，新增 `why` 与 `evidence_to_verify`，把“为什么值得做”和“哪些事实需要人工核实”显式交给用户，禁止编造趋势数据。
2. **口播脚本**：第一句直接进入问题、场景或结论；禁用“大家好 / 今天聊聊 / 话不多说 / 欢迎收看”；中间不堆“首先、其次、最后”；脚本只含可朗读文本，并在输出前按开场、单一结论、句长、行动建议、合规提醒和字数自检。
3. **分镜**：固定“钩子 → 问题 → 要点 / 步骤 → 结论 / 行动”的叙事骨架；相邻镜头不得重复画面和构图；每镜写清主体、动作、环境、景别或构图、光线与情绪，并给字幕和画面大字留空间。
4. **配图**：只表现一个主体和一个明确动作，使用真实可理解的中国家庭 / 社区日常场景；禁止文字、数字、UI、药品和医疗器械特写，禁止治疗前后对比、惊恐、血腥及虚假疗效暗示。
5. **封面**：带着正文前 240 字作为内容线索，不只照标题猜；9:16、中上部单一焦点、底部标题安全区、真实生活场景、柔和自然光，继续禁止文字和医疗符号。

## 直接导出 MP4（2026-10-18）

- 「成片」步骤渲染成功后直接显示「导出 MP4」，不再要求先导出整套制作包。
- 弹出的保存框默认落到系统视频目录，文件名使用「视频标题 + 年月日-时分」，自动处理 Windows 非法文件名字符。
- 只允许导出签名仍与当前分镜、配音、配图、模板和背景音乐一致的有效成片；修改上游内容后按钮隐藏，必须重新渲染。
- 用户没写扩展名时自动补 `.mp4`；保存到原成片位置时不会复制覆盖自身。
- 制作包导出保持原逻辑，仍会在 `video.mp4` 中携带当前有效成片。
