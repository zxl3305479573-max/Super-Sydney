# 小红书模块设计

> 状态：已实现（2026-10-13）。实现时相对草案的调整与踩过的坑见文末「实现说明」。
> 思路来源：@kongge_space《小红书运营 Skill》（2026-08-23），其开源实现见 `github.com/SpaceZephyr/creator-buddy/tree/main/xhs-Skills`。
> 本草案完全沿用推文的拆法——**定位、选题、写作、视觉、复盘五个环节 + 一个总控，共 10 个能力，三条标准链路**——只把「Skill」翻译成桌面端里的子模块、数据与界面。

## 目标

在「内容」分组里给公众号、视频之外加第三条流水线：把运营一个小红书号从头到尾拆开，每一环都有可单独使用的工具，再由总控按用户当前卡点串成链路。单个能力能独立用，真正的价值在串起来。

## 定位与边界

- 复用现有内容基础设施：内容 API / 图片 API 配置与调用开关、「公众号资料」式的资料隔离、内容方向分类表（含方向 note 里的合规约束与配图风格模板）、按任务加锁（`request-lock.ts`）。关掉内容 API 开关时三条流水线一起停。
- 合规规则跟随内容方向注入提示词；健康方向保持「严格科普不诊疗」。
- **不自动发布**：小红书没有面向个人号的发布接口，模块的终点是「发布包」（标题、正文、标签、3:4 图组），由人手动发。这与公众号「外部发布必须人工确认」的契约一致。
- **热点数据走红狐 API**（与推文路线 1 一致），key 由用户在设置里填写、存进 `secret-store`（系统加密），不写进仓库或明文配置。联网搜索作兜底；应用内小红书窗口作后续补充（主要供账号诊断读主页）。页面读取的红线是只读公开可见或用户自己在应用内浏览到的页面，不逆向接口、不绕验证。
- 除热点数据外，其余能力只依赖已有的内容 API / 图片 API。

## 能力总览（5 环节 · 10 个能力）

| # | 环节 | 推文 Skill | 本模块子模块 | 作用域 | 一句话 |
|---|---|---|---|---|---|
| 1 | 总控 | space-xhs-buddy | **向导（Router）** | 账号 | 先问清卡在哪，再推荐链路与下一步 |
| 2 | 定位 | space-xhs-positioning | **账号定位** | 账号 | 引导式问答 → 赛道、定位句、人设三件套、内容支柱、前 20 篇选题、冷启动路径 |
| 3 | 选题 | space-xhs-hotspot | **热点选题** | 账号/笔记 | 关键词 → 领域热门笔记，转成选题候选 |
| 4 | 写作 | space-xhs-title | **标题工坊** | 笔记 | 15 种标题法批量出候选，逐条评分、合规标注、角色推荐、A/B 建议 |
| 5 | 写作 | space-xhs-writer | **正文写作** | 笔记 | 7 种笔记类型，开头 3 行 / 分段骨架 / 结尾互动 / 标签组合 + 发布前 14 项检测 |
| 6 | 视觉 | space-xhs-cover | **封面** | 笔记 | 3:4 首图，重点是标题层级、主体识别、移动端可读性 |
| 7 | 视觉 | xhs-html | **图文卡片（HTML）** | 笔记 | 长文拆成 ≥6 张 3:4 卡片，HTML 渲染后逐页导出 PNG；先给风格候选与 6/7/8/9 页方案 |
| 8 | 视觉 | space-xhs-image | **生图信息图** | 笔记 | 模型直接出位图：单图或 6–9 张信息图，固定风格模板 |
| 9 | 复盘 | space-xhs-account-audit | **账号诊断** | 账号 | 8 维打分（定位清晰度、内容垂直度、封面统一性、标题钩子率、更新节奏、互动率、爆款率、粉丝转化），定位卡点给改动 |
| 10 | 复盘 | space-xhs-note-analytics | **笔记复盘** | 账号 | 导入后台笔记数据，六层漏斗归因，多篇横向找规律 |

两种作用域决定了数据怎么存：**账号级**（定位、诊断、复盘、向导）每个账号一份、长期演进；**笔记级**（选题落地后的标题、正文、视觉）每篇一条任务、走流水线。

## 三条标准链路

- **链路 A · 从零起号**：定位 → 热点选题 → 正文 → 标题 → 封面 + 图文卡片/生图 → 发布包
- **链路 B · 日常产出**：热点选题 → 正文 → 标题 → 封面 + 图文卡片/生图 → 发布包
- **链路 C · 诊断改进**：先用笔记复盘定位卡在漏斗哪一层，再对症：
  - 曝光低 → 账号诊断（标签 / 定位 / 权重）
  - 曝光够、点击率低 → 标题工坊 + 封面
  - 点击够、互动低 → 正文写作（开头留人 / 价值兑现）

注意顺序沿用推文：**先写正文，再起标题**（标题要基于已经写成的内容做搜索词覆盖与收藏动机）。

## 各子模块

### 1. 向导（总控）

- 桌面端里没有「模型自选 Skill」的问题，但仍有「功能太多不知从哪下手」的问题，所以保留总控，形态改成模块首页。
- 首页三块：账号现状卡（有无定位、最近复盘结论、在制笔记数）→ 一句话描述卡点（「刚起号」「不知道写什么」「数据不好」…）→ 输出推荐链路与下一步按钮。
- 规则优先：无定位档案 → 链路 A；有复盘结论 → 按漏斗层直接跳链路 C 对应环节；其余 → 链路 B。只有自由描述时才调一次模型做分类，结果落到上面三种之一。

### 2. 账号定位

- 多轮引导式问答（每轮模型给 1–3 个问题，用户回答），直到收敛；可中途保存、随时续问。
- 产出存为账号的「定位档案」：赛道选择、定位句、人设三件套（账号名 / 简介 / 视觉）、内容支柱（3–5 个）、前 20 篇选题、冷启动路径。
- 定位档案是后续所有环节的上下文：选题按内容支柱过滤，正文与标题按人设语气写，封面按人设视觉统一。前 20 篇选题可一键转成笔记任务。

### 3. 热点选题

- 输入关键词，查询领域热门笔记（标题、互动数、发布时间、链接、作者），按内容支柱归类，给出可借鉴的角度并转成选题候选。
- 数据源按优先级降级，统一成同一个适配器接口：
  - **① 红狐 API（主力）**：`POST https://redfox.hk/story/api/xhs/search/search`，请求头 `X-API-KEY`，body 为 UTF-8 JSON：`keyword`（空串 = 全站热门，可多词分别查）、`pageNum`、`pageSize`（≤50）、`startDate` / `endDate`（`yyyy-MM-dd`，默认近 7 天）、`source`。成功时 `code === 2000`。
    - 返回 `data.articles[]`，单条字段（2026-10-13 实测）：`id`、`title`、`desc`、`cover`、`createTime`、`shareInfoLink`、`topicsName`、`authorId` / `authorNickname` / `authorFans`、`interactiveCount` / `likedCount` / `collectedCount` / `commentsCount` / `sharedCount`、`totalScore` / `relevanceScore` / `popularityScore` / `recencyScore`；另有 `hotTopics`、`relatedSearches`（拓词）、`latestHotArticles`（主结果太少时参考）、`tips`。
    - 库内数据范围：昨天 ~ 30 天前，每日 7 点更新；不是实时数据。互动数在展示时按推文做法模糊化（<5000 原值、5000+、Nw+），不反推精确值。
    - `relatedSearches` 直接用作拓词建议；`authorFans` 支撑「账号量级」判断；`topicsName` 喂给标签组合。
  - **② 联网搜索（兜底）**：没配 key、key 失效（401）或重试仍失败时，按关键词查通用搜索引擎（`site:xiaohongshu.com <关键词>` 等），只用标题、摘要与来源；所有结论标「未经互动数据验证」，互动量级、账号量级、互动结构、热度趋势四项写「需配置数据源」，不靠猜补齐（同推文兜底规则）。
  - **③ 应用内小红书窗口（后续）**：复用 `site-view.ts` 的做法，挂独立会话分区（`persist:sydney-xhs`）的 WebContentsView，用户自己登录、搜索后点「读取当前结果」。补红狐没有的实时数据与评论区；主要用途是账号诊断读主页。
- 页面读取红线（② ③ 适用，写进代码与界面说明）：
  - 只读页面上已经渲染出来的内容，不逆向签名参数、不直连内部接口、不伪造请求头；
  - 遇到验证码、滑块、登录墙立即停止并把窗口交给用户，不尝试绕过；
  - 限速（同一来源两次请求间隔数秒、单次查询条数有上限）、单账号、无代理池；
  - 只存选题需要的字段（标题、摘要、互动数、链接），不存评论者等他人个人信息。
- 已知风险：红狐按 key 计费 / 限额，数据有 1 天延迟；② 的可用率与字段完整度会波动；③ 用的是用户自己的账号，频繁读取有被风控的可能。界面上写明。
- 查询结果按「关键词 + 日期范围」缓存 24 小时（红狐每天只更新一次，重复查没有新数据，还费额度）。所有来源都拿不到数据时，退化为「模型 + 定位档案给选题建议」，并明确标出没有真实热度数据。

### 4. 标题工坊

- 输入：当前笔记正文（默认）、或一个主题、或一条现成标题。
- 按 15 种标题方法各出若干候选；每条给评分（搜索词覆盖、人群指向、收藏动机等）、合规风险标注（夸大、绝对化、医疗功效词等）、按用途分角色推荐（主推 / 备选 / 测试用），并给 A/B 测试建议。
- 用户选定一条写回笔记；方法清单与评分维度做成数据表，后续可调。

### 5. 正文写作

- 7 种笔记类型：种草测评、干货教程、个人故事、合集清单、避雷拔草、好物分享、经验复盘。类型决定结构模板。
- 产出：开头 3 行、分段骨架与正文、结尾互动、标签组合；可直接编辑。
- 发布前 14 项检测：规则能判的（字数上限、标签数、emoji 密度、敏感词 / 绝对化用语、外链与联系方式）本地算，判断类（开头是否留人、价值是否兑现）交模型，结果逐项列出、可一键回改。

### 6. 封面

- 3:4 竖版首图。输入：主题、标题，可选人物 / 产品 / 背景素材（本地图片）。
- 复用现有图片接口，尺寸改为 3:4；提示词由程序拼「用途 + 标题层级 + 主体」，画风取内容方向的配图风格模板，并叠加定位档案里的人设视觉。
- 提供移动端缩略预览，检查小尺寸下标题是否可读。

### 7. 图文卡片（HTML）

- 把正文 / 教程 / SOP / 清单拆成 ≥6 张 3:4 卡片。开始前给风格候选与 6/7/8/9 张页数方案供选择。
- 模型只产出结构化分页内容（每页标题、要点、强调句），HTML 由本地模板渲染——不让模型直接写 HTML，保证排版稳定、风格可控。
- 推文是 62 种风格、在浏览器里手动截图；本模块先内置少量风格模板，用 Electron 离屏窗口逐页 `capturePage` 直接导出 PNG。

### 8. 生图信息图

- 需要模型直接出位图时用：单图或 6–9 张信息图。
- 推文固定为一种风格；本模块做法是给它一个独立的固定风格模板（可在内容方向里覆盖），与封面风格分开维护。
- 与图文卡片二选一或混用，最终都进入同一个「图组」，可排序、可替换单张。

### 9. 账号诊断

- 输入自己或竞品的主页：在应用内小红书窗口打开主页后点「读取主页」（同热点选题的来源 ③ 与红线），读出简介、粉丝数与已加载的近 N 篇笔记标题、封面、互动数；也可手动粘贴或导入表格。
- 8 个维度打分 + 卡点定位 + 可执行改动清单；诊断自己的账号时，改动可回写为定位档案的修订建议。
- 每次诊断存一份快照，可前后对比。

### 10. 笔记复盘

- 导入创作者后台导出的笔记数据表（沿用公众号「文章数据」的思路：列名别名匹配、表格 → 记录、记录 ↔ 笔记任务按标题与日期匹配）。
- 六层漏斗归因（曝光 → 点击 → 阅读/完播 → 互动 → 收藏/转发 → 涨粉，具体层级待按后台实际字段定），标出每篇卡在哪一层、为什么、下一条改什么；多篇横向对比找规律。
- 复盘结论喂给向导，驱动链路 C 的跳转。

## 笔记流水线与状态

- 笔记任务状态：`idea → body → title → visual → packaged`，表示「已经确认到哪一步」。
- 失效规则（与视频模块同一套思路）：
  - 改正文 → 已选标题标「需复核」，图文卡片 / 信息图标「需重新生成」，发布包标「需要重新导出」；
  - 改标题 → 封面标「需复核」（封面上有标题字），发布包需重新导出；
  - 换笔记类型 → 正文骨架失效，状态退回 `idea`。
- 发布包导出到知识库 `08-小红书/<时间戳>-<id>-<随机串>-<标题>/`：`笔记.md`（frontmatter、标题、正文、标签、检测结果、合规声明）、`01.png…NN.png`（首张为封面）。目录名带时间戳与随机串，永不覆盖。
- 导出硬门槛：正文非空、已选标题、至少一张图（封面）。

## 模块边界（拟定文件）

- `desktop/services/xhs-pipeline.ts`：纯函数规则层——笔记状态推导、失效规则、导出门槛、发布前检测里的本地规则、漏斗归因计算。
- `desktop/services/xhs-workflow.ts`：所有模型调用与结果校验（向导分类、定位问答、选题、标题、正文、诊断、复盘解读、卡片分页）。
- `desktop/services/xhs-hotspot.ts`：数据来源适配器接口、红狐客户端（请求、`code` 校验、指数退避重试、字段归一化、互动数模糊化）、联网搜索兜底、降级顺序、结果缓存。
- `desktop/services/secret-store.ts`：新增红狐 key 的存取（沿用现有内容 API key 的加密方式），设置页加「红狐 API Key」一栏与「测试连接」。
- `desktop/services/xhs-view.ts`：应用内小红书窗口（独立会话分区的 WebContentsView），提供「读取当前搜索结果 / 主页」，遇验证页即停。页面解析规则放纯函数 `xhs-page-parse.ts`，方便用保存的页面样本做单测。
- `desktop/services/xhs-cards.ts`：图文卡片模板渲染（HTML 字符串，纯函数）；离屏截图放主进程。
- `desktop/services/xhs-stats.ts`：后台导出表格解析与笔记匹配（参照 `article-stats.ts`）。
- `desktop/services/xhs-store.ts` / `xhs-export.ts`：持久化与发布包落盘。
- `desktop/shared.ts`：`XhsAccount`、`XhsPositioning`、`XhsNote`、`XhsNoteStage`、`XhsTitleCandidate`、`XhsCheckItem`、`XhsAudit`、`XhsNoteStat` 与 `SydneyApi` 的小红书方法。
- `desktop/main.ts`：数据表 `xhs_accounts`、`xhs_notes`、`xhs_hotspot_cache`、`xhs_audits`、`xhs_note_stats`；独立 IPC 命名空间 `xhs:*`，不进 `state:get`。
- `desktop/renderer/xiaohongshu/`：首页（向导）+ 账号区（定位 / 诊断 / 复盘）+ 笔记流水线（选题 → 正文 → 标题 → 视觉 → 发布包）。笔记流水线沿用 `.flow-*` 骨架，新增 3:4 卡片网格与移动端预览样式。

## 错误处理

- 未开启内容 API 开关：所有生成按钮报「请先允许内容 API 调用」，不发请求。
- 红狐 401：提示 key 无效或过期（附获取地址 `https://redfox.hk/settings/api-keys`），本次降级到联网搜索；`code !== 2000`：原样展示 `msg` 并检查参数（日期格式、`pageSize ≤ 50`）；网络失败指数退避重试 3 次后降级。
- 联网搜索失败 / 被拦截：提示是哪个来源、卡在哪一步（搜索、读页、解析），退化为无热度数据的模型建议，不静默伪造数据。
- 应用内窗口出现验证码 / 登录墙：停止读取，提示用户在窗口里自行处理后再点读取。
- 页面结构变化导致解析为空：报「页面结构可能已更新」，不把空结果当成「没有热门笔记」。
- 模型返回非法 JSON / 空结果：报错并保留上一步已有产物。
- 同一笔记并发长操作：按笔记加锁，可切到其它笔记并行。
- 导出中途失败：清理本次新建的目录，不留半个包。

## 建议的实现顺序

1. 数据骨架：账号 / 笔记表、`xhs:*` IPC、首页与笔记流水线空壳。
2. 链路 B 的最小闭环：正文写作 → 标题工坊 → 封面 → 发布包（不依赖联网数据，最快可用）。
3. 定位 + 向导（补齐链路 A）。
4. 图文卡片 / 生图信息图。
5. 笔记复盘 + 账号诊断（链路 C）。
6. 热点选题：先接红狐（接口稳定、字段齐，可以较早做，甚至提到第 3 步），再补联网搜索兜底，最后做应用内窗口（同时供账号诊断读取主页）。页面解析最容易随改版失效，单独维护。

## 实现说明（2026-10-13）

相对上面草案的调整：

- **笔记流水线多了一步「发布前检测」**：步骤为 选题 → 正文 → 标题 → 视觉 → 发布前检测 → 发布包。状态不再手动维护，而是按内容推导；「上游改过、下游需复核」靠内容指纹（`basisJson`）判断，人工可以点「仍然可用，确认」重新盖章。
- **笔记多了「经验与素材」字段**：正文只基于它写亲身经历，没有素材就按科普 / 整理口吻写，「亲历分享」类标题同理。
- **14 项检测**：9 项本地规则（标题 ≤20 字、正文 ≤1000 字、信息量、标签数与格式、emoji 密度、绝对化 / 功效用语、外链与引流、段落长度）+ 5 项模型判断（开头留人、价值兑现、方向合规、人设一致、结尾互动）。模型不可用时本地 9 项照常出结果。
- **信息图复用卡片分页**：先拆分页（模型），再选择本地模板渲染（免费）或按页生图（计费），两者进同一个图组。
- **与公众号隔离**（取代早先「绑定内容方向」的做法）：只借用内容 API / 图片 API 的连接配置，不读公众号的内容方向、style.yaml 的读者与语气、配图模板。读者、语气、人设只来自小红书自己的定位档案；封面按笔记的选题、正文摘要和用户写的画面要求生成，画风用小红书自己的通用模板。
- **数据表**：`xhs_accounts`、`xhs_notes`、`xhs_hotspot_cache`、`xhs_reports`（诊断与复盘解读共用，按 kind 区分）、`xhs_note_stats`。

实测踩过的坑：

- **卡片截图**：隐藏窗口的高度会被夹到屏幕高度以内；普通隐藏窗口在主窗口显示时不出帧，复杂一点的页面截图会一直挂起；对还没导航过的 webContents 挂调试器发命令会让主进程直接崩掉。最终做法：离屏渲染（offscreen）+ 先载入 about:blank 再挂调试器 + `Emulation.setDeviceMetricsOverride` 设成 1080×1440 后按裁剪框截图。
- **联网搜索**：Node 直接请求必应拿到的是给爬虫的降级页面（结果与关键词无关），必须用浏览器窗口读结果页；`site:xiaohongshu.com` 几乎搜不到东西，查询词改为「小红书 关键词 爆款笔记」等。
- **未登录的博主主页**：笔记卡片不给笔记 id（链接只有 `/explore/`），读取时按标题生成 id、链接指回主页；诊断只需要标题与点赞，不受影响。主页笔记是异步加载的，读早了会是 0 篇。
- **红狐**：请求体必须是 UTF-8；偶尔多给一条，按请求条数截断；`source` 字段任意值都可以。
