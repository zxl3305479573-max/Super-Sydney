# Sydney 自我总结进化系统

Sydney 是个人 AI 工作成长平台的桌面端 MVP。项目代码位于 `D:\Super-Sydney`；Obsidian 知识库保持独立，首启默认使用旧项目文档记录的 `D:\33054\Documents\persornal\Sydney`，也可以在桌面端“隐私与设置”中选择其他目录。应用会拒绝把项目目录本身用作知识库。

## 首阶段功能

- Electron + React + TypeScript 桌面端。
- SQLite 事件数据和设置保存在 Electron `userData`，不写入项目目录或知识库。
- 显式开始、暂停、继续、停止应用活动记录；默认停止。
- 只采集允许应用的名称、窗口标题和使用时长，敏感窗口和禁止应用会被跳过。
- 支持手动记录、事件确认/忽略/修改/删除。
- 可将当日事件写入知识库的 `02-每日总结/YYYY-MM-DD.md`；只更新 Sydney 标记区块，保留文件其他手工内容。
- 可在隐私设置中显式启用 Codex 桌面端对话采集。只有 Sydney 正在记录时，才会监听 `~/.codex/sessions` 此后新增的用户提示词与 `final_answer` 最终答复。
- 独立的「公众号」模块：自带文章任务库，桌面端直接调用外部 API 完成选题、任务书、证据计划、初稿、审稿、配图与排版预览，不依赖 pi 或 WeWrite CLI。

Codex 对话采集默认关闭，不回填历史，不读取 `archived_sessions`，不保存 analysis、commentary、工具调用、工具输出或终端内容。只接受明确标记为 `final_answer` 的 assistant 输出，不接受缺少阶段标记或其他阶段的中间内容。采集结果只进入本地待确认事件，带有“敏感内容，仅本地”标识；删除 Sydney 事件不会删除 Codex 原会话。Codex 事件不会自动写入日报、工作流或云同步载荷。

## AI 对话采集（Codex / Claude Code）

两类采集都默认关闭，且只有 Sydney 正在记录时才运行；启动时把已有会话定位到文件末尾，不回填历史。

- **Codex**：监听 `~/.codex/sessions`（支持 `CODEX_HOME`）。默认只采集 Codex 桌面端；打开「同时采集 Codex CLI / IDE 插件」后，终端 `codex` 与 VS Code 插件会话也会进入，它们的最终答复取自 `task_complete` 事件，注入的环境上下文会被过滤。
- **Claude Code**：监听 `~/.claude/projects`（支持 `CLAUDE_CONFIG_DIR`，可在设置中追加目录）。只保留用户真正输入的提示词（斜杠命令记为 `/命令 参数`）和每轮最后一条可见答复；工具结果、思考过程、hook 输出、`!` 终端命令、子代理（sidechain / subagents）全部跳过。一轮在 `end_turn`、下一条提示词、用户中断或 30 秒无新内容时结束；之后若有补充文本会更新同一事件。
- **过程元数据**：每轮额外记录工具名称次数、被改动文件的路径、用时、是否被中断和模型名（`ai_trace_json`），不保存工具参数、命令行或输出。
- **性能**：目录列表按目录 mtime 缓存；最近 10 分钟内有写入的会话每秒检查，其余每 15 秒检查一次；文件被截断或重写时从头读取。

## 自我进化（侧栏「自我进化」）

四个环节都由你手动触发，生成物一律是待审核状态。

### 1. AI 协作复盘

统计所选时间段（7/14/30 天）内未被忽略的 Codex / Claude 对话，写入 `03-进化记录/AI协作复盘-YYYY-MM-DD.md`（只更新标记区块，保留手工批注）：重复 3 次以上的相似请求（候选 skill / 斜杠命令 / 脚本）、纠正与打断、项目分布、工具组合、热点文件、斜杠命令使用次数、规则候选状态和知识库复用。笔记只包含 80 字以内的提示词摘要和元数据。

### 2. 项目规则补丁（AGENTS.md / CLAUDE.md）

同一项目目录出现 ≥2 次纠正或打断时，复盘会生成一个「规则候选」，附带每次纠正和被纠正的上一轮对话摘要作为依据。在「自我进化」里可以：

- 手动填写规则，或点「AI 生成规则」让 DeepSeek 根据依据写 1–3 条（需开启允许发送到 DeepSeek）；
- 「预览补丁」查看会写入哪些文件、新增哪几行：项目里已有 AGENTS.md / CLAUDE.md 就写入已有的，都没有则新建 AGENTS.md；
- 「确认写入」后规则追加在 `<!-- SYDNEY:RULES:START/END -->` 区块里，已存在的规则不会重复写；预览后文件若被改动，会要求重新预览；
- 「撤销写入」只在文件仍是 Sydney 写入后的原样时才恢复，手动改过的文件不会动；驳回的依据不会再次生成候选。

### 3. 周报接入复盘

「生成周报」（今日工作或自我进化页）会统计本周的 AI 对话，自动填写「重复出现的问题」「可以自动化的工作」「值得深入学习的方向」「可制作的教程、模板或公众号选题」，并链接本周的复盘笔记和规则写入情况。本周没有 AI 对话时保持原来的模板。

### 4. 知识库复用度

采集时额外记录 Claude `Read` 工具读取的文件、Codex 命令参数里出现的 `.md` 路径（命令本身不保存）。复盘会回看近 90 天，列出 AI 最常用到的笔记，以及超过 60 天未修改、也没被 AI 用到的「候选归档」笔记（跳过 00-系统、02-每日总结）。只读取文件名和修改时间，不读取笔记内容。

### 5. 经验卡片

「提炼经验卡片」把**已确认**的 Codex / Claude 对话（每次最多 20 条，每条只提炼一次）发给 DeepSeek，抽取「坑 → 解法」，写入 `04-工作流/经验卡片/<主题>/<标题>.md`（`status: review`）。同名卡片再次出现时只追加「出现记录」，并重建 `04-工作流/经验卡片/索引.md`。

## 屏幕后台采样

屏幕采样默认关闭，只有用户开启屏幕采样并开始 Sydney 记录时才会定时执行。采样前会检查当前活动应用和窗口标题：禁止应用、敏感窗口、未通过允许应用名单的窗口不会截图。通过检查的主屏幕帧使用 Electron 系统安全存储保护的密钥进行 AES-GCM 加密，保存在应用数据目录，按设置的保留时间自动清理，不上传、不写入 Obsidian，也不进行 OCR 或内容分析。

## DeepSeek AI 整理

DeepSeek 整理默认关闭，只有用户在设置中打开“允许发送到 DeepSeek”，并在单条待确认事件上点击“AI 整理”时才会发起请求。Codex 事件只发送用户提示词和 Codex 面向用户展示的最终答复；工具调用、终端输出、会话路径和其他本地元数据不会发送。模型结果只作为本地草稿保存，必须人工应用和确认后才进入后续沉淀流程。

在启动桌面端前配置 OpenAI 兼容环境变量：

```powershell
$env:SYDNEY_LLM_BASE_URL = "https://api.deepseek.com/v1"
$env:SYDNEY_LLM_API_KEY = "your-deepseek-api-key"
$env:SYDNEY_LLM_MODEL = "deepseek-chat"
npm start
```

API key 只在 Electron 主进程环境中读取，不写入设置文件、SQLite、Obsidian 或云端。

也可以直接在桌面端“隐私与设置”中保存、替换或删除 DeepSeek API Key。Windows 下密钥使用系统凭据加密保存到 Electron 应用数据目录，界面只显示掩码。程序内密钥优先于环境变量；删除程序内密钥后才回退到环境变量。不要继续使用已经在聊天或日志中暴露的旧密钥，应先在 DeepSeek 控制台撤销并重新生成。

首阶段不采集键盘输入、私人聊天和密码；屏幕画面仅在用户显式开启屏幕后台采样后按安全过滤规则加密保存；不启用云端同步。AI 整理、文件关联、周报、内容选题和工作流生成属于当前已有的显式操作能力，仍需用户主动触发和人工确认，不能把自动采样直接当作已确认事实。

## 公众号工作流

桌面端新增独立的「公众号」一级模块。它与其他模块在导航与内容上完全分离，不显示活动采集、事件时间线或屏幕帧等记录内容。

### 桌面端原生内容管道（不依赖 pi 或 WeWrite CLI）

公众号模块可以脱离 agent 独立运行：文章任务、阶段状态与产物存在应用自己的 SQLite（`content_tasks` 表），内容生成由 Electron 主进程直接调用外部 API。

- 「桌面端创作」标签：先选**内容方向**（一级）与**具体方向**（二级）再新建文章任务，然后依次生成**选题 → 任务书 → 主张与证据计划 → 初稿 → AI 审稿**，可随时手动编辑与保存。两级分类都由你自己维护，不限定领域：默认只有「中老年健康科普」及其 4 个具体方向，可在「环境与配置 → 内容方向」里改名字、加约束、增删方向。选好标题后可以点「自动生成」一次跑完后四个阶段；审稿未通过时可点「按审稿意见修改正文」让内容 API 按审稿意见重写一版新初稿（改完需要重新审稿）。
- 内容 API：在公众号自己的「环境与配置」中填写接口地址、模型和密钥，并显式允许主动调用；密钥使用系统安全存储，兼容现有 DeepSeek 配置。证据计划只列待核实主张，AI 审稿不是联网事实核查。
- 修改标题、方向、类别或正文会使旧审稿和成稿失效。生成前自动保存编辑；推送默认只允许当前正文通过审稿，未通过审稿时会在二次确认（并列出待处理问题）后按当前正文推送，避免误发旧版本。
- 应用不调用 WeWrite CLI：创作、配图、预览与草稿推送全部在桌面端完成。
- 图片 API：直接调用「环境与配置」里配置的图像端点生成封面，也支持手动选择本地图片。封面提示词带上主题、正文提要与内容方向约束，按文章实际写了什么来画。
- 正文配图：初稿步骤可「AI 生成正文配图」，按小标题自动挑位置，逐张按所在段落写提示词并生成，再把图片插进正文；画面里可以出现文字、字母、数字和图表数值（提示词要求写对、写清楚）。导出时图片一并复制到知识库 `assets/`，推送草稿箱时自动上传到微信图片接口并替换成 mmbiz 地址（微信侧不认本地路径）。
- 多张候选挑选：配图步骤的「每处出几张」可选 2–3 张，这时 AI 只生成候选、不直接落正文；候选面板按位置列出每张缩略图（默认选中第一张），点「采用选中的 N 张」才写进正文或作为封面，点「放弃候选」则全部丢弃。候选不落库，是临时状态；挑图期间改过正文会拒绝插入并要求重新生成，避免按旧行号插错位置。
- 以前生成的图也能挑：配图与封面步骤都有「从已生成的图里挑」，不打图片接口也不计费，直接把这篇任务配图目录里出过的图（封面与正文配图分开，各列最近 9 张）按当前位置列出来换上去。同一个位置再挑一张会替换掉原来那张，而不是越插越多；只接受本任务配图目录里的文件，界面回传的外部路径一律拒绝。
- 排版模板：内置 5 套内联样式主题（中老年友好 / 简洁资讯 / 书卷 / 杂志 / 温暖亲和），在编辑器右上角按文章切换；主题只影响呈现，不会让已通过的审稿失效。应用内预览由主进程渲染，本地配图会转成 data URI 显示。
- 审稿门槛：审稿返回 `pass` 才把初稿写为成稿，否则保留在待修改状态。审稿只是建议而非硬门槛：未通过审稿也能导出到 Obsidian 或推送草稿箱，但必须逐次确认。
- **推送草稿箱（直连微信 API，不经任何 CLI）**：主进程直接完成 `cgi-bin/token` → `material/add_material`（上传封面为永久素材）→ `draft/add`（创建草稿）。只创建草稿，绝不群发；推送前二次确认，推送后记录 media_id 并置为已推送状态。
  - access_token 按 appid 缓存（提前 300 秒过期），命中 40001/40014/42001 时自动刷新并重试一次。
  - 微信接口出错也常返回 HTTP 200，因此错误判定以 body 的 `errcode` 为准。
  - 提交草稿时保留中文原文（不转 `\uXXXX`，否则微信会把转义序列当正文存储）。
  - 正文渲染为全内联样式 HTML（微信会剥离 `<style>`），摘要按 UTF-8 字节截断到 120 字节以内，标题限 64 字，并追加 AI 辅助声明脚注。

### 环境与配置（可直接在桌面端填写保存）

「环境与配置」是可编辑表单而非只读看板，分组为：公众号资料、读者定位、内容方向、模板与排版、合规与禁忌、图片服务、微信草稿箱，以及可折叠的自检明细。

「内容方向」是两级树：一级方向写这个账号的内容领域（例如「中老年健康科普」「科技与数码」），它下面的每条具体方向对应编辑部常说的"栏目"。每一级都能写自己的约束说明（note），这些文字会原样进入写作与配图的提示词——所以换方向就等于换一套写作红线，健康类的不诊疗、不宣称疗效等要求只属于那条默认方向。两级分类落库在本机 SQLite，保存时同步回 `style.yaml` 的 `topics`（所有具体方向名）与 `default_topic`（默认具体方向）。

其中与写作直接相关的几组（模板与排版、公众号资料、读者定位、内容方向）也直接放在「创作流水线」界面里：顶部一块「创作设置」，摘要一行常显，展开即可编辑，与「环境与配置」互通。目标读者、篇幅、语气会进入内容 API 的生成提示词，默认具体方向决定「新建文章任务」两级下拉框的初值。

- 保存后写入本机 `~/.wewrite/style.yaml` 与 `~/.wewrite/config.yaml`（Windows 上权限收紧为仅属主可读）。
- 默认类别写入 `default_topic` 并排到内容方向第一位；新建任务时下拉框会以此为默认。
- 敏感字段（图片 API Key、微信 AppSecret）只以掩码回传到界面；表单留空表示保留原值，明文不会进入渲染进程。
- YAML 由受控序列化函数生成并使用双引号转义，已用 PyYAML 与自有解析器双向验证过含 `#`、`"` 与换行的值。

### 与 WeWrite / agent 的关系

应用只读写 `~/.wewrite/style.yaml` 与 `config.yaml`，这两份文件同时被 agent 侧的 WeWrite skill 读取，因此在对话里用 agent 写作时风格配置保持一致。原先的「WeWrite 兼容」标签（读取 `~/.wewrite/runs` 并调用 CLI 预览、评分、推送）已于 2026-10 下线。

- skill 目录用 Windows 目录联接指向 `~/wewrite/skills/*`，更新只需 `git pull`，**不要再跑 `install.sh`**（Git Bash 会把联接降级成目录复制并冲掉定制）。

## 变现 · 站点模块（AI 代充）

侧栏「变现」下新增「AI 代充」：把现成的第三方站点（代充 / 发卡后台）直接嵌进桌面端操作。可以添加多个，同一时刻显示选中的那个，不在应用里重做一套订单界面。

- 每个站点一个 `WebContentsView`，由主进程挂在窗口上，渲染进程只负责报承载区域的位置（`site:bounds`）。所以站点页面不受它自己的 `X-Frame-Options` / `frame-ancestors` 影响，也不走预览用的 srcdoc 沙箱；报上来的矩形会被夹进窗口可视区，小到看不出是块区域就先不挂视图。
- 站点列表与当前选中项存在应用数据目录的 `site.json`（兼容最早只有 `{ url }` 的单站点格式）：地址只接受 http/https，没写协议按 https 补全（`localhost:3000`、`pay.example.com:8080` 这类「主机:端口」不会被误判成协议头），`file:`、`javascript:`、`data:` 一律拒绝，列表上限 20 个。
- 界面提交的整份列表在主进程硬校验：坏地址、缺 id、重复 id 都拒绝，并回报是第几个站点；名称留空时按域名兜底。
- 切换站点只是把上一个视图摘下来、把下一个挂上去：已经打开过的站点常驻会话，切回来不会重新加载，登录态与滚动位置都在（代价是打开过的站点各占一个渲染进程）。只有从列表里删掉某个站点时才关掉它的页面。
- 站点共用独立会话分区 `persist:sydney-site`，但登录态与 cookie 只留在它自己那里：应用不读站点的 cookie、不往页面里注入脚本，也不把它写进数据库；站点打开的新窗口（支付页、客服链接）交给系统浏览器，麦克风、摄像头、通知、定位等权限默认全部拒绝。
- 离开这个模块只是把当前视图摘下来；弹层（手动记录 / 事件详情）打开时也会先收起视图，避免原生视图盖住弹层。
- 这块状态刻意不进 `state:get`：站点状态变化频繁（每次导航、每次标题变化），走独立的 `site:*` 通道，避免整个界面跟着重拉。
